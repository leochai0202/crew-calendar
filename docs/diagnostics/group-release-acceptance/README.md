## 分组发布和 last-good

全部通过时保持现有 dated/latest 聚合稿行为。部分通过时写入
`PARTIAL_RELEASE`，只更新通过组的中英文正式文件；失败组的旧文本以及整日
dated/latest 合并正文均不覆盖。metadata 明确 `aggregate_current=false`，
不把旧合并稿当成本次全部任务；失败组的当前正式输出链接为空。
`.success` 只允许提交已经通过校验的正式分组及其状态，不含未校验半套版本。

相同任务指纹的已完成部分发布不重复调度；通过组文件缺失或真实排班变化会重新
调度。航班取消仍首次失效并产生一次可见 NO_TASK 记录，持续无任务不重复触发，
恢复后重新调度。原 cron、slot_date、指纹字段和外籍分组规则未改。
权威资料补正后需要重新验收/明确重检，不能靠相同排班指纹自动证明冲突已解决。

## 本轮已确认的程序修复

- 每组独立收集/校验错误，任何一版失败都阻断该组的整套双语发布。
- 同一来源冲突即使不生成英文，也不自动放行。
- 有证据的机场英文身份作为配置数据供通用定向航线解析使用。不同航线条目
  被正常排除而不是删除重要适用事实；未知身份仍不猜测。
- 对照原页修正明确误译，保留中文、原英文、来源页、hash及审阅记录。
  包括机位引导、三边航向、推开许可、单发加速高度、ILS测距和已确认程序转弯。
  新英文不能在运行时自由生成，也不能越过数字、单位、时序或来源校验。
- 跑道分配、OLPAB/OBLAP、180/8量纲、PAPI四类未确认技术数据没有修改。
- 不新增条数上限，不压缩适用事实，不改模板个人资料或天气策略。

机场身份交叉核查仅用于名称/代码，不用作运行程序权威：公司手册502/634/661/1021页、
已有 `airport_iata.json`，以及
[十堰地服经营者的本站身份](https://www.universalaviation.aero/locations/china/shiyan-zhsy/)和
[韩国航空气象机关的JEJU/RKPC身份](https://www.amo.go.kr/weather/airport.do?icaoCode=RKPC)。
没有将这些网页天气读入航前 Agent。

   任务成功。回滚后再次核对 NO_TASK、latest/dated状态和下次调度，不自动重跑登录。
